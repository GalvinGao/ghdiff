# Localization

The migrated interface copy is in Paraglide catalogs, including accessibility
labels, errors, confirmations, count variants, userscript text, and the visible
labels adapted from the pinned Pierre packages. English is the source.

The first batch contains 20 locales: `en`, `zh-Hans`, `es`, `fr`, `de`, `ja`,
`ko`, `pt-BR`, `ru`, `hi`, `ar`, `id`, `vi`, `tr`, `pl`, `it`, `uk`, `nl`, `fa`,
and `bn`. This is a developer-audience coverage plan, not a measured ranking.
Each catalog has 760 messages.

## Ownership and runtime

- Edit `messages/{locale}.json`; never edit generated `src/paraglide/`.
- `project.inlang/settings.json` declares locales and the locally installed
  message-format plugin. `i18n.config.mjs` shares compiler options with Vite,
  including one output layout so CLI checks and development use the same files.
  The local Git review client uses the same generated messages and sets document
  language/direction before mounting.
- Home and setup keep their globe menu. The review page groups language and
  color scheme inside the display-settings cog. Language selection stores a
  cookie and reloads the page. `src/server.ts` scopes locale detection to each
  request. English is the fallback; review URLs retain GitHub's paths.
- The document sets `lang` and `dir`. Arabic and Persian prose is RTL. Pane
  placement, code, paths, URLs, branch pairs, and SHAs stay LTR. Technical
  interpolations in RTL catalogs use Unicode isolates; the diff's translated
  count captions are isolated from their LTR code container. User comment prose
  uses `dir="auto"`.
- Call messages at rendering/request time, including in getters for option
  tables. Module-initialization calls freeze a locale across requests.
- `src/lib/locale.ts` provides locale-aware number/list formatting. Relative
  times use `Intl.RelativeTimeFormat`. Keep all repositories, no selected
  repositories, and exactly one deleted comment separate from grammatical plural
  categories: Russian 21 is not exactly one comment.
- Use complete messages and locale-specific plural selectors. Rich messages use
  `ParaglideMessage` with named React renderers; interpolation remains text. The
  watch-offer sentence takes the actual named control's label so it cannot
  disagree with the button it describes.
- Repository identifiers, authors' content, code, and protected product names
  remain data. External GitHub error details may retain GitHub's language.
- `src/userscript.js` is bundled into `src/lib/server/ghdiff.user.js`, the
  template the `/ghdiff.user.js` route fills with the deployment's origin and
  one `@match` per host it serves, retaining its installation metadata. It
  matches GitHub's document language to an enabled locale, including regional
  tags, without mapping Traditional Chinese to Simplified Chinese. Otherwise it
  uses English. Bump the source version when changing the installed artifact.
- `scripts/pierre-i18n.mjs` adapts visible labels in pinned Pierre modules,
  which do not expose translation callbacks. Exact-source checks fail on
  incompatible package updates. The plugin runs for hosted app, local CLI
  client, and highlight-worker builds.
- Unexpected route and application-shell errors use localized recovery copy.

## Editing and checks

Use the message editor from the `localize` skill. The installed editor rejects
some valid inlang shapes: multiple selectors, semantic branches that omit an
input, and number-formatting variants in languages with only the `other` plural
category. For those cases, edit through a JSON parser and verify actual
Paraglide compilation and branch tests. Do not insert unused placeholders or
remove locale-aware number formatting to satisfy that editor limitation.

```sh
pnpm i18n:compile
pnpm i18n:check
pnpm test
pnpm typecheck
pnpm lint
pnpm fmt:check
pnpm build
pnpm exec wrangler deploy --dry-run
```

Dev, build, test, and typecheck compile first. Compilation verifies that the
compiler emitted every source message. The checker guards key coverage/order,
interpolation parity and accidental repetition, rich-text nesting, protected
names, selector defaults, literal JSX/accessibility text, and import-time calls.
Tests render every locale's messages and representative count branches, exercise
semantic exact-number cases, verify regional matching and rich-text safety, and
interleave requests with different locales.

These checks do not establish natural-language quality. Review the changed
screens at desktop and phone sizes, including expanded copy and mixed scripts.
The userscript install card stacks on phones to leave room for longer prose.
Vite explicitly minifies the SSR bundle; check Worker compressed size when
adding locales or server dependencies.

## The forge layer — 2026-10-13

Moving every forge call behind one `Forge` interface brought 95 new messages and
retired 29. Twenty of the new ones take the forge's name as a `{forge}`
parameter where the retired ones spelled GitHub. The rest are what the layer
adds: the draft review — staged comments, the **Draft** chip, and the verdict
that publishes them — resolved threads, the media proxy, the typed failures and
the sign-in each write asks for, the review-request chip, the forge gate's
sentence about what a deployment serves, and the setup page's answer when it
serves nothing. One existing message, the left bar's signed-out note, now also
names the review-request chip.

The translations began as a single pass by the authoring agent (Claude), built
on each catalog's existing terms and register. On 2026-10-15 the authorized
Codex fallback (`gpt-5.6-terra`) audited all 96 messages — the 95 new ones and
the rewritten signed-out note — in each of the 19 target catalogs: 1,824 rows in
95 batches of at most 20 per locale, every requested identifier returned.
Antigravity was not used: `agy` is not installed on the machine that ran the
audit. The audit proposed 672 changes; 531 were applied as proposed or with an
edit, and a dozen follow-ups carried the same fix to messages it had not
flagged.

What changed: a resolved thread is no longer "closed" in Russian and Ukrainian;
a thread's **Open** state reads as a state, not the action, everywhere; the
calques for "this ghdiff serves" were replaced; Arabic and Persian now isolate
`{forge}` as they already isolated every host, sha and revision; Turkish and
Polish stop putting a case ending on the forge name; Russian draft comments use
one term. What was overridden: a change that swapped an established term in a
few messages only (forge, verdict, issue, diff, Not Found), advice to restore
English's plural branches in a locale whose CLDR categories differ, isolates
around the literal names GitHub and ghdiff, which no catalog isolates, Japanese
proposals that only removed the spaces the catalog keeps between Japanese and
Latin text, and Arabic rewrites of masculine imperatives into impersonal forms —
a catalog-wide register change, left for a pass of its own rather than mixed
into one screen.

## GitLab support — 2026-10-13

Merging the GitLab forge brought its interface copy into the catalogs: GitLab
sign-in and personal access tokens, the setup steps for an instance, merge
request wording beside pull request wording, the threads on a merge request
itself, the rule that keeps a draft on a changed line, and the GitLab-only

changed sources: `userscript_description`, which now names merge requests, and
`setup_screen_nothing_to_set_up`, which now names GitLab hosts. `GitLab` joined
the checker's protected names. Two of the new messages are the GitLab forge's

which used to reach the screen in English.

The translations began as a single pass by the authoring agent (Claude), built
on each catalog's existing terms and register. On 2026-10-15 the authorized
Codex fallback (`gpt-5.6-terra`) audited all 141 messages in each of the 19
target catalogs: 152 batches, 2,678 of 2,679 rows returned; the one Korean row
it skipped, `route_set_up_access`, was checked by hand and matches its GitHub
counterpart. Antigravity was not used: `agy` is not installed on the machine
that ran the audit. The audit proposed 1,157 changes; 922 were applied as
proposed or with an edit, and sweeps carried the same fix through the rest of a

protected name ghdiff and was rewritten; `pnpm i18n:check` caught it.

Open for a human reviewer: Persian uses one term, "درخواست ادغام", for both a

("درخواست کشش" and "پول‌ریکوئست"). Changing it means changing every Persian
message that names a pull request, so it is left as it was and named here.

Merge request follows each catalog's pull request choice — kept in English where
pull request is, transliterated where it is — except Persian, whose term for a
pull request already reads as a merge request, so its copy names the forge where
both appear in one sentence. Arabic and Persian isolate every host, project
path, sha and revision.
